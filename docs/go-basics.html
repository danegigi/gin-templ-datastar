Go Language Documentation

Modern Go development is module-first. You normally create a project folder anywhere, run `go mod init`, and let the Go tool manage dependencies through `go.mod` and `go.sum`.

* Use modules, not GOPATH/src, for almost every new project.
* Use go install package@version to install command-line tools.
* Use go get only to add, upgrade, or downgrade module dependencies.
* Use go work for local multi-module development; do not treat it as a production dependency manager.

1. Installation and Environment

Install Go from the official Go downloads page or a trusted package manager. After installation, verify the version and environment variables:

go version
go env GOROOT GOPATH GOMOD GOWORK

Modern projects do not need to live under GOPATH. GOPATH is still used for the module cache and binaries installed by go install, but your source code can be anywhere. Ensure your binary path is exported:

export PATH="$PATH:$(go env GOPATH)/bin"

Useful Environment Commands:

go env # Print Go environment
go env -w GOPRIVATE=github.com/your-org/ # Private modules configurations
go env -w GOTOOLCHAIN=auto # Allow automatic toolchain selection

4. Packages, Imports, and Visibility

The first statement in every Go file is the package declaration.
Files in the same folder must use the same package name.
Executable programs use package main and define func main().
package main

import (
    "fmt"
    "example.com/app/internal/mathx"
)

func main() {
    fmt.Println(mathx.Add(2, 3))
}

Exported: Start with an uppercase letter (User, NewServer).

Unexported: Start with a lowercase letter (user, newServer).

internal/ packages can only be imported by code inside that specific parent directory tree.

6. Control Flow & Loop Scope Mechanics

if n := len(items); n == 0 {
    return errors.New("empty")
}

// Traditional for loop
for i := 0; i < 10; i++ {
    fmt.Println(i)
}

// Go 1.22+ integer range expression
for i := range 10 {
    fmt.Println(i)
}

// Map iterations
for key, value := range m {
    fmt.Println(key, value)
}

The Loop Pre-Iteration Variable Fix

The Problem (Go 1.21 and earlier)

Historically, Go reused the exact same memory address for the loop iteration variable across every iteration loop execution. If you passed a pointer of the loop variable, or captured it inside a closure (such as a goroutine or an event callback), every single reference wound up pointing to the final mutated value of the loop.

The Modern Fix (Go 1.22+)

Since Go 1.22, loop variables created by for loops are per-iteration variables. This prevents accidental closure bugs in goroutines and callbacks natively without requiring manual semantic workarounds.

Comparison Example

package main

import (
	"fmt"
	"sync"
)

func main() {
	items := []string{"A", "B", "C"}
	var wg sync.WaitGroup

	// --- STANDARD LOOP CONCURRENCY ---
	// In Go 1.21 and below, this would likely print "C", "C", "C".
	// In Go 1.22 through Go 1.26+, this correctly prints "A", "B", "C" (unordered).
	fmt.Println("--- Modern Loop Semantics ---")
	for _, item := range items {
		wg.Add(1)
		go func() {
			defer wg.Done()
			fmt.Println(item) 
		}()
	}
	wg.Wait()

	// --- MANUAL PRE-ITERATION FIX (For Legacy Contexts) ---
	// What it fixes: Manually shadowing/redefining the variable inside the block 
	// forces a unique memory reference per block execution context in old compilers.
	fmt.Println("\n--- Manual Pre-iteration Variable Fix (Legacy) ---")
	for _, item := range items {
		wg.Add(1)
		itemFixed := item // Explicit allocation capture
		go func() {
			defer wg.Done()
			fmt.Println(itemFixed)
		}()
	}
	wg.Wait()
}

defer schedules functions to execute immediately when the surrounding function returns. Commonly used to close resources, release mutexes, and catch unexpected panics.

Explicit Errors

Go handles exceptions using explicit value errors. Wrap contextual errors with %w and inspect them using errors.Is or errors.As:

var ErrNotFound = errors.New("not found")

func load(id string) (User, error) {
    if id == "" {
        return User{}, fmt.Errorf("load user: %w", ErrNotFound)
    }
    return User{}, nil
}

// errors.Is example
user, err := load(id)
if errors.Is(err, ErrNotFound) {
    // Handle specific not found branch
}
if err != nil {
    return fmt.Errorf("handler failed: %w", err)
}
// errors.As example
type ValidationError struct {
	Field string
	Msg   string
}
func (e *ValidationError) Error() string {
	return e.Field + ": " + e.Msg
}
func createUser() error {
	return fmt.Errorf(
		"create user failed: %w",
		&ValidationError{
			Field: "email",
			Msg:   "invalid email",
		},
	)
}
err := createUser()
var validationErr *ValidationError
if errors.As(err, &validationErr) {
	fmt.Println("Field:", validationErr.Field)
	fmt.Println("Message:", validationErr.Msg)
}


Note:

errors.Is - Compare against a known error value

errors.As - Find/extract an error of a particular type

Use panic only for programmer blunders or unrecoverable system initialization errors—never basic bad data or user inputs.

8. Data Structures and Mutation

Slices

names := []string{"Dane", "Alex", "Gigi"}
names = append(names, "Gane")

// Delete an element at index 1
names = append(names[:1], names[2:]...) 

// Duplicate/Copy a slice

Maps

counts := map[string]int{"a": 1}
counts["b"] = 2

value, ok := counts["a"]
delete(counts, "b")

Pointers

Slices, maps, and channels are reference-like types; structs and arrays are passed by value (copied). Use pointers for value mutation and memory footprint reduction:

func increment(n *int) {
    *n++
}

x := 1
increment(&x) // x is now 2

10. Generics

Generics parameterize functions and structures across a defined set of compatible types.

type Number interface {
    ~int | ~int64 | ~float64
}

// Generic validation algorithm
func Sum[T Number](values []T) T {
    var total T
    for _, v := range values {
        total += v
    }
    return total
}

// Generic Data Structure Struct
type Pair[T any] struct {
    First  T
    Second T
}

// Type constraint transformations
func MapKeys[K comparable, V any](m map[K]V) []K {
    keys := make([]K, 0, len(m))
    for k := range m {
        keys = append(keys, k)
    }
    return keys
}

Advanced Generic Pattern: Generic Chainable Methods (Builder Pattern)

By using generic parameters, you can write types that provide a fluent, chainable API for any data structure while ensuring static type check safety at compilation time.

package main

import "fmt"

// Stream provides fluent chaining over slice collections of type T
type Stream[T any] struct {
	items []T
}

func NewStream[T any](items []T) *Stream[T] {
	return &Stream[T]{items: items}
}

// Filter chains down slices based on matching conditional predicates
func (s *Stream[T]) Filter(predicate func(T) bool) *Stream[T] {
	var filtered []T
	for _, item := range s.items {
		if predicate(item) {
			filtered = append(filtered, item)
		}
	}
	s.items = filtered
	return s
}

// Collect terminates the chain and unloads the current state
func (s *Stream[T]) Collect() []T {
	return s.items
}

func main() {
	numbers := []int{10, 15, 20, 25, 30}
	
	result := NewStream(numbers).
		Filter(func(n int) bool { return n > 12 }).
		Filter(func(n int) bool { return n%2 == 0 }).
		Collect()

	fmt.Println(result) // Output: [20 30]
}

var wg sync.WaitGroup
for i := range 5 {

        defer wg.Done()
        fmt.Println("worker", workerID)
    }(i)

Channels and Select

jobs := make(chan int)
results := make(chan int)

go func() {
    defer close(jobs)
    for i := range 10 {
        jobs <- i
    }
}()

go func() {
    defer close(results)
    for job := range jobs {
        results <- job * 2
    }
}()

for result := range results {
    fmt.Println(result)
}

Context Interruption & Management

Always pass context.Contextas the first argument parameter for long-running workflows, API round-trips, and persistent transactions.

ctx, cancel := context.WithTimeout(context.Background(), 2*time.Second)
defer cancel()

select {
case <-ctx.Done():
    return ctx.Err()
case result := <-ch:
    _ = result
}

Structured Concurrency with errgroup (wg.Go)

Standard sync.WaitGroup coordinates structural timing but does not handle error cascades or context cancellations out of the box. Using golang.org/x/sync/errgroup handles tracking tasks using a functional execution model .Go(), catching errors, and forwarding cross-context shutdowns automatically.

package main

import (
	"context"
	"fmt"
	"net/http"
	"time"

	"golang.org/x/sync/errgroup"
)

func main() {
	// WithContext builds a derived context canceled automatically if any step reports an error
	g, ctx := errgroup.WithContext(context.Background())

	urls := []string{
		"https://httpbin.org/delay/l",
		"https://httpbin.org/status/404", // This causes an error path
		"https://httpbin.org/delay/2",
	}

	for _, url := range urls {
		// Launch tasks concurrently via .Go()
		g.Go(func() error {
			req, err := http.NewRequestWithContext(ctx, http.MethodGet, url, nil)
			if err != nil {
				return err
			}

			client := &http.Client{Timeout: 5 * time.Second}
			resp, err := client.Do(req)
			if err != nil {
				return err
			}
			defer resp.Body.Close()

			if resp.StatusCode >= 400 {
				return fmt.Errorf("http error on %s: status %d", url, resp.StatusCode)
			}

			fmt.Printf("Fetched %s\n", url)
			return nil
		})
	}

	// Wait handles synchronizations and returns the first recorded non-nil error
	if err := g.Wait(); err != nil {
		fmt.Printf("Execution halted with group error: %v\n", err)
	} else {
		fmt.Println("All fetches resolved nicely!")
	}
}

func CopyFile(dstName, srcName string) error {
    src, err := os.Open(srcName)
    if err != nil { return err }
    defer src.Close()

    dst, err := os.OpenFile(dstName, os.O_WRONLY|os.O_CREATE|os.O_TRUNC, 00644)
    if err != nil { return err }
    defer dst.Close()

    return err
}

16. Build Tags

Build tags constrain compilation targets based on environment conditions, operational requirements, or cross-compilation platforms.

//go:build linux
package platform
func Name() string { return "linux" }

Filename suffixes such as _linux.go, _windows.go, _amd64.go, and _arm64.go are also automatically resolved by the Go compiler toolchain to filter platform-specific compilation units.
