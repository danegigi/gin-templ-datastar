Allocating with make and new

Go has two built-in allocation functions, make and new. They look similar but do different jobs, and choosing the right one is a common early stumbling block. The short version:

  • new(T) allocates zeroed storage for a value of type T and returns a pointer to it (*T). It works for any type.
  • make(T, ...) initializes the internal data structure of a slice, map, or channel and returns a ready-to-use value of type T (not a pointer). It works only for those three types.

The reason for two functions: slices, maps, and channels are not just memory — they are handles to a runtime data structure (a backing array with length/capacity, a hash table, a queue with a lock). make sets that structure up; new only hands you zeroed memory, which for these types is a nil, unusable value.

Pointers with new

package main

import "fmt"

type Config struct {
    Host string
    Port int
}

func main() {
    // new(T) allocates a zeroed T and returns *T.
    p := new(int)        // p is *int, points to 0
    *p = 42              // dereference to set the value
    fmt.Println(*p)      // 42

    // Works for structs too — all fields start at their zero value.
    cfg := new(Config)   // cfg is *Config -> &Config{Host:"", Port:0}
    cfg.Host = "localhost"
    cfg.Port = 8080
    fmt.Println(*cfg)    // {localhost 8080}
}

Use case: new is rarely used in idiomatic Go for structs — &Config{Host: "localhost", Port: 8080} (a composite literal with the address-of operator) is clearer and lets you set fields inline. new earns its place mainly when you need a pointer to a primitive (like *int or *bool) — for example an optional/nullable field in a struct that maps to a database column, or a counter you pass by pointer so a function can mutate it.

Slices with make

package main

import "fmt"

func main() {
    // make([]T, length, capacity)
    // length = elements you can index right now (all zero-valued)
    // capacity = room in the backing array before a reallocation is needed
    s := make([]int, 3, 10)
    fmt.Println(s, len(s), cap(s))  // [0 0 0] 3 10

    s = append(s, 1, 2, 3)          // fits within cap, no reallocation
    fmt.Println(s, len(s), cap(s))  // [0 0 0 1 2 3] 6 10

    // Common shorthand when you only care about length:
    buf := make([]byte, 1024)       // a 1 KB read buffer, all zero
    _ = buf
}

Use case: use make with a capacity when you know roughly how many elements you'll append — pre-sizing avoids repeated backing-array reallocations as the slice grows, which matters in hot loops. The classic example is building a result slice: out := make([]Result, 0, len(input)) then appending in a loop. Read buffers (make([]byte, 4096)) are the other everyday case.

Maps with make

package main

import "fmt"

func main() {
    // A nil map (var m map[string]int) can be READ but panics on WRITE.
    // make gives you a writable map.
    m := make(map[string]int)
    m["alice"] = 30
    m["bob"] = 25
    fmt.Println(m["alice"])  // 30

    // Optional size hint — pre-allocates buckets for ~N entries to reduce
    // rehashing as the map grows. It's a hint, not a hard limit.
    counts := make(map[string]int, 100)
    _ = counts
}

Use case: always make a map before writing to it — a nil map (declared with var m map[string]int and never initialized) panics on assignment. Pass the size hint when you know the rough number of keys (e.g. building a lookup from a slice of records) to cut down on rehashing. Maps are the go-to for de-duplication (map[string]struct{} as a set) and grouping/counting.

Channels with make

package main

import "fmt"

func main() {
    // Unbuffered channel: a send blocks until another goroutine receives.
    // Use for synchronization / handoff between goroutines.
    done := make(chan bool)
    go func() {
        fmt.Println("working...")
        done <- true          // signal completion
    }()
    <-done                    // block until the goroutine signals

    // Buffered channel: holds N values before a send blocks.
    // Use as a queue / to smooth bursts between producer and consumer.
    jobs := make(chan int, 5) // capacity 5
    jobs <- 1
    jobs <- 2
    close(jobs)               // no more sends; receivers can still drain
    for j := range jobs {
        fmt.Println("job", j)
    }
}

Use case: an unbuffered channel (make(chan T)) is a synchronization point — the sender waits for a receiver, so it's ideal for signaling "done" or handing a single value between goroutines. A buffered channel (make(chan T, n)) decouples producer and consumer up to n items — use it as a work queue, a semaphore to cap concurrency (make(chan struct{}, maxWorkers)), or to absorb bursts so a fast producer isn't blocked by a slower consumer.

Rule of thumb: reach for make for slices, maps, and channels; reach for a composite literal (&T{...}) for structs; reach for new only when you specifically need a pointer to a primitive's zero value.
